## Pre-PR checklist — theme-token work (design tokens, `.theme-*` classes, `globals.css`)

Run through these before opening any PR that adds or changes a runtime design token, a `.theme-*` utility class, or an animation. Each rule exists because a real PR shipped the mistake; the fuller incident write-ups are in the root `CLAUDE.md` "Storefront frontend" section.

1. **Tailwind v4 namespace collision.** A new runtime design token must NOT be named in a Tailwind theme namespace: `--color-*`, `--radius-*`, `--spacing-*`, `--text-*`, `--font-*`, `--shadow-*`, `--ease-*`, `--animate-*`, `--breakpoint-*`, `--tracking-*`, `--leading-*`, `--blur-*`, `--aspect-*`, `--perspective-*`. In v4 those names ARE the utility scale — the `rounded-*` / `p-*` / `gap-*` / `text-*` utilities compile to `var(--<name>)` with no fallback, so defining one (in `@theme` OR plain `:root`) moves that whole utility family on every unrelated call site. Use a bespoke `--theme-*` / `--motion-*` / `--section-*` / `--grid-*` style name, on plain `:root`, never `@theme`. It fails **silently at runtime** — only inspecting the built CSS or `app/globals.css.test.ts` catches it. Incident: B1 put `--radius-sm/-md/-lg` in the `@theme` block; `rounded-sm/-md/-lg` shifted +2 to +4px across ~88 unrelated call sites (account, bio, brands, collections, checkout, cart, modals). Reverted by renaming to `--theme-round-*` in `fix/radius-tokens-out-of-theme-block`.

2. **Full swap, never additive.** A `.theme-*` class and the hardcoded Tailwind class it replaces have equal CSS specificity, so stylesheet order decides which wins — unpredictable. Always REMOVE the hardcoded class from the element; never leave both. Responsive replacements: one base declaration + one `@media` override, and the base rule must appear before the media block in source. Incident: B2's `py-8` → `theme-section-py`, `gap-4 sm:gap-6` → `theme-grid-gap`, `mb-4` → `theme-heading-gap` swaps.

3. **JS animations self-gate on reduced motion.** The blanket `@media (prefers-reduced-motion: reduce)` rule near the top of `globals.css` zeroes CSS transitions and animations only (`0.01ms`, not `0`, so `transitionend` still fires). Any JavaScript-driven animation — rAF loops, WAAPI, `setInterval`, pointer-tracked transforms, `element.animate()` — must check `matchMedia('(prefers-reduced-motion: reduce)')` itself and skip. Precedent: `HeroSlideshow` and `lib/announcement-rotation.ts` each self-gate.

Also: `globals.css` must `postcss.parse` clean — `app/globals.css.test.ts` asserts it. A `*/` inside a CSS comment (e.g. writing a `--foo-*` glob followed by `/`) closes the comment early, PostCSS throws, and turbopack still exits 0 while every hand-written class silently vanishes from the output.

**Proposed, not built — a shared reduced-motion helper.** Item 3 is a per-item tax across the later motion phases (fly-to-cart, count-up, magic-line, parallax, header scroll-behaviour, custom cursor, mobile drawer). A `useReducedMotion()` hook (a `matchMedia` subscription returning a boolean, ~10 lines, mirroring `lib/use-scroll-value.ts` which was pre-shipped in Phase A for the same reason) would remove it. Build it as the first task of whichever phase adds the second JS animation, not before.
