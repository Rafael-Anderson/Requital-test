## Design

- One reader: `GET /public/orders/lookup?token=[&shop=]` (`PublicService.lookupOrder`), rebuilt in `backend/src/public/order-lookup.ts` as a field-by-field `PublicOrderView` (no row spread, no `SELECT *`). The tracking page keeps working (additive fields; `deliveryDate` is now a `YYYY-MM-DD` string; `currency` is now the ORDER's, was the shop's).
- Cross-tenant decision: `shop` is optional. When given (the confirmation page always sends its own slug) a token of another shop is the same 404 as an unknown token; without it the token alone resolves (tracking page, unchanged).
- Route `orders/[id]` renamed `orders/[token]`; gateway `successUrl` and the checkout redirect carry the tracking token. A numeric (or any non-token-shaped) segment shows "We cannot open this order from here" and makes NO request. `?paid=1` is gone from the success URL and ignored if present.
- Payment wording is `derivePaymentView(order)` only (`lib/order-confirmation.ts`): paid / refunded / failed / confirming (poll every 2s, max 20 visible ticks, paused while the tab is hidden, "Check again" restarts) / unconfirmed / cancelled / pay on delivery / pay on pickup. `paymentFailed` = a `paymenttransaction` row with status failed while the order is still unpaid.
- Browser purchase event and cart clearing now happen only when the server says paid AND a purchase stash exists (this browser started that online checkout). Online-payment checkout never cleared the cart before; this clears it, only in that case.
- `layout.tsx` for the route: noindex and `referrer: no-referrer`.

## Flags for review

- A token in a URL path is a bearer capability. Same class as `/orders/track?token=` and `/survey?token=`, but note the Meta pixel / GA4 `page_view` (only after marketing consent) include the page URL, so the token reaches the ad platform on this page. A `page_location` scrub in `lib/analytics.ts` is a possible follow-up.
- The lookup now returns `customerAddress` (delivery orders) and the item `note`, which the old tracking response deliberately omitted; the token already proved ownership and the page needs it.
- In-flight gateway sessions created before deploy carry `/orders/<id>?paid=1`: they land on the safe "cannot open" state with a Track link (the payment itself is unaffected).
- `CreateCheckoutSessionParams.orderNumber` is required (human label for Stripe).
- CAPI `eventSourceUrl` still uses `/orders/<id>` (now a safe state page); harmless.
