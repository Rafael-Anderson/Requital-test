# W2: shopper cookies (fix/customer-cookie-path)

Root cause: customer cookies were `Path=/public/<slug>`; the storefront browser calls `/api/public/<slug>/...`
(next.config.ts rewrite), a URL that Path never matches. All three cookies (access, refresh, CSRF) were stored
and never sent, in `next dev` and in a production build alike. There is no non-proxied browser shape: `apiBase()`
returns `/api` in any browser.

Fix: Path=/ with the shop slug in the cookie NAME (`__Host-req-customer-at-<slug>`, `-rt-`, `-csrf-`), picked by the
slug in the request URL. `__Host-` is now legal for customer cookies (production), which also stops a sibling
subdomain shadowing them. One CSRF instance per slug (memoised, capped at 500). Logout clears the three new cookies
and the three pre-fix ones. Old cookies are never read.

Trade-offs for CLAUDE.md: three cookies per shop signed in to, sent on every request to the storefront origin (httpOnly,
same origin), the refresh token included (it used to go only to /auth/refresh); cookie names are case-folded slugs
(`[a-z0-9-]{1,63}`); a CSRF cookie per shop. Replaces the "Path=/public/<slug>" paragraphs in CLAUDE.md (Auth mechanism,
Platform admin CSRF, custom-domain Phase 5, Batch S/T premise correction).
