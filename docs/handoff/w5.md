# W5 driver hardening (fix/driver-hardening)

Migration `20261105100000_driver_hardening` (data only): NULLs `deliveryrunstop.proofPhotoUrl` (the key is kept, nothing is lost) and scrubs finished `driver-link:%` / `delivery-code:%` job payloads.

1. Proof photos are private. `StorageProvider.read` (local + S3 GetObject), `StorageService.readProof`, staff-only `GET /delivery-runs/:id/stops/:stopId/proof-photo` (run via loadRun: shop + outlet scoped, `deliveries.view` against the fetched run's outlet; no-store, nosniff, CSP sandbox). Staff detail returns `hasProofPhoto`, never a URL. main.ts mounts `blockPrivateUploads` before the static handler so `/uploads/delivery-proof/*` is 404 (pre-existing files too; they stay readable through the endpoint). Deletion goes through a `delete_proof_photo` job (retry, backoff, dead letter): on pending-stop removal, photo replacement, an orphan upload, and PDPL anonymisation (`anonymiseCustomerDeliveryProofs`, called from `CustomerAccountService.anonymiseCustomer`).
2. `JobsService.enqueue(..., { sensitive: true })` flags a payload; `completeJob(id, payload)` and the dead-letter step in `failJob` replace `body`/`bodyText`/`html` with `[scrubbed]` in the same statement; `listDeadLetter` scrubs again on read; retry of a scrubbed dead letter is 409. The stubs in `common/email.ts` / `common/whatsapp.ts` withhold the body for sensitive jobs. Used by the driver-link WhatsApp job and the delivery-code email job.
3. `DeliveryRunsService.dispatch` is one transaction: run CAS + `OrdersService.moveToOutForDeliveryTx` for every order. Any ineligible order refuses the whole dispatch (409 with `details`); nothing is dropped from a run silently. Audit, affiliate sync and the customer "out for delivery" message run after commit (`OrdersService.afterStatusChanged`, shared with `updateStatus`). The old `order_changed` stop failure reason is no longer produced by dispatch (the admin label stays for old rows).
4. Leftovers: reconciliation response is now `{ data, truncated }` (fetches limit+1, drops the possibly cut oldest run when truncated); NULL `cashCurrency` falls back to the order's currency, not AED.
