## 2. The real stock policy (verified)

- **Storefront checkout and draft-order complete** (`public.service.ts:1593-1620`, `orders.service.ts:446`): stock is reserved AT CREATION through `consumeForOrderItems(-1, throwOnInsufficientStock: true)` with the CAS guard `AND stockQuantity >= ?` (`products.service.ts:3886`). Per-line `allowNegative = !trackInventory || continueSellingOutOfStock` (`:3760`) skips the guard. So: tracked and not continue-selling -> cannot oversell (loser 409, whole order rolled back); otherwise may go negative.
- **Admin order confirm** (`orders.service.ts:758` -> `adjustStockForOrder` `throwOnInsufficientStock: false`): ALWAYS allows negative. This is the only place "always allow" is true.
- **`updateItems` increase on a confirmed order**: plain products 409, recipe products warn (`ingredientStockWarnings`) and still save. `continueSellingOutOfStock` does NOT bypass this (the code comment says that is deliberate; pinned).
- **Shop toggle `autoDeductIngredientStock=false` disables ALL stock decrement, plain products included** (F12 below).

Ledger conservation: for an (outlet, ingredient) whose row only moved through logged movements, `SUM(stockmovement.delta) = outletingredientstock.stockQuantity`. Holds across every path tested except `PATCH /products/stock/bulk-adjust`, which logs nothing (F4b).
