# C3 fulfilment selector (handoff note, coordinator removes)

Investigation (file:line on a5c79e4b):
- There is NO shop-level delivery/pickup toggle. The only toggles are per outlet: outlet.deliveryEnabled / pickupEnabled
  (backend/src/db/types.ts:864, outlets.service.ts, public.service.ts:1221 listOutlets payload). Delivery additionally needs
  deliveryRadiusKm when enabled (outlets.service validation). Shop-level things that gate a type: the per-type payment flags
  (shop.delivery/pickupPayment*, public.service.ts:100-109, enforced by assertPaymentMethodAvailable ~2274), shop
  deliveryHours/pickupHours (assertFulfillmentOpen ~2325), outlet hours/closedOverride, and the outlet delivery radius
  (resolveDeliveryFee ~2160, delivery only).
- Server enforcement already existed: public.service.ts:1544-1549 returns 400 "This outlet does not offer delivery/pickup".
  It was untested; now pinned in backend/test/storefront-checkout.e2e-spec.ts (describe "fulfilment type must be enabled...").
  No createOrder validation changed, so no /security-review needed.
- Storefront before: useCheckoutForm split outlets into deliveryOutlets/pickupOutlets and stored orderType in state; the
  selector always rendered one button per available type (a lone "Delivery" or "Pickup" button for single-type shops); the
  "neither" case replaced the whole page with red text and no Place order button.
After: storefront/lib/fulfilment.ts (resolveFulfilmentOptions, effectiveOrderType, fulfilmentUnavailableMessage);
useCheckoutForm is outlet-first and derives orderType; components/checkout/FulfilmentSection.tsx is shared by both layouts.
Behaviour changes worth knowing: a pickup order now ALWAYS sends "Pickup at <outlet>" as customerAddress (it used to send a
stale delivery address typed before switching); canSubmit also requires the payment method to be in the offered list;
the outlet picker now lists every outlet offering anything (suffix "(pickup only)" / "(delivery only)") instead of
filtering by the chosen type; no AddonPrompt when nothing can be ordered.
Not changed: gift-card-only carts go through the same fulfilment as any cart (backend has no special case); contact_to_order
shops never reach checkout through the cart; hours/closed outlet remain separate messages, not part of the options.
Screenshots: docs/handoff/c3-shots (before-/after-<scenario>-<width>.webp, dev indicator hidden).
